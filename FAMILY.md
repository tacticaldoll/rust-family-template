# Family Governance

The shared governance of the tacticaldoll family of Rust repositories. The skeletons under
`skeleton/` are its concrete form; `scripts/family-check.py` is its mechanical projection. When this
file and a skeleton disagree, fix the disagreement in the template before any repository is aligned
to either.

## Principles

- **Copied, never referenced.** A repository carries a complete copy of the shared text. It does
  not link to, depend on, or vendor this template; a clone of one repository is self-describing.
- **Sibling-blind.** A brick names no other product. Only a consumer app names what it composes,
  because composition is exactly the knowledge a consumer owns. The template is provenance, not a
  sibling: a repository may name it as its skeleton source.
- **Checked from the template outward.** Drift is detected by running `family-check.py` from here
  against a repository. No repository runs, imports, or knows about the check.
- **Shared form, owned substance.** Process, integration, and conformance text is shared.
  Product identity, axioms, review questions, extra gates, and law are owned by each repository.

## Profiles

| Profile | For | Crates | Law focus |
|---|---|---|---|
| `brick` | a sans-I/O library core | `<name>-contract` (core), `<name>` (re-export facade), `<name>-governance` | the whole core is pure; the facade holds no logic |
| `app` | a consumer application | `<name>` (lib + bin), `<name>-governance` | `crate::domain` is a pure functional core that never imports `crate::shell`; keeping effects in the shell is review-governed |

A repository may add crates beyond its profile's minimum; each one needs a boundary so the
coverage test holds.

## Repository Settings

Every family repository, and this template, carries the same GitHub settings.
`scripts/repo-settings.py` compares a repository against them from the template outward and, with
`--apply`, writes them.

| Setting | Value |
|---|---|
| merge methods | squash only (merge commits and rebase merges disabled) |
| squash defaults | title from the pull request title, message from the pull request body |
| head branches | deleted on merge |
| `main` protection | pull request required (0 approvals); required status checks are every job in `.github/workflows/ci.yml`, with the branch up to date; enforced for administrators; linear history; no force pushes; no deletion |
| GitHub Releases | none; `CHANGELOG.md` is the release notes (reported, never removed by `--apply`) |

A job's display name is its required-check name, which is why the four family jobs share their
names across the family and why a renamed job is a settings change.

## Decisions

The choices that shaped this governance, with their reasons.

- **OpenSpec ends at sync.** Sync merges verified delta specs into `openspec/specs/` and removes
  the change directory. A separate archive gate added a state nothing reads. The
  `openspec/changes/archive/.gitkeep` scaffold that `openspec init` creates stays; nothing is
  archived into it.
- **OpenSpec is validated with one pinned CLI.** The Definition of Done and CI run
  `npx -y @fission-ai/openspec@1.13.2 validate --all --strict --no-interactive`. Validators
  disagree across releases — 1.4.1 rejected a requirement whose `SHALL` sat past its first line,
  which 1.13.2 accepts — so an unpinned local CLI could fail specs CI passes, or the reverse.
  Moving the pin is a template change that lands in every repository together.
- **Law is projected at the root.** `AGENTS.<name>-law.md` beside `AGENTS.md`, freshness-gated —
  Tianheng's documented adopter shape.
- **One governance crate per repository.** A single observable command in the Definition of Done
  and CI, independent of the workspace graph it judges.
- **The changelog is a ledger.** Unreleased work lives in OpenSpec, pull requests, and
  `BACKLOG.md`; a guard keeps every version heading linked.
- **MSRV 1.88 for the workspace.** A repository may declare a lower floor for its published crates
  as an extra gate.
- **Every crate states whether it publishes.** Cargo inherits `publish` from `[workspace.package]`
  only through `publish.workspace = true`, so a workspace default protects nothing on its own.
  Each crate declares `publish = true` or `publish = false`, and the check refuses a crate that
  declares neither.
- **Release tags keep `release: X.Y.Z`.** The squash subject is `chore(release): prepare X.Y.Z`
  and the annotated tag message is `release: X.Y.Z`. Every tag is a release tag: named `vX.Y.Z`,
  annotated with exactly that message (a signature may follow it), and naming a `CHANGELOG.md`
  version. `family-check.py` reads the checkout's local tags and reports any other tag name, a
  lightweight tag, another message, or a tag with no entry.
- **No GitHub Release objects.** `CHANGELOG.md` is the single set of release notes, and its footer
  links resolve to the tag page without a Release. A Release would be a second copy that drifts;
  one repository once carried three, so `repo-settings.py` reports any.
- **Disposition Discipline is adopted, not imposed.** It rules out consumer-gated deferral, which
  is product policy; a brick that grows bet-first or behind a consumer graduation test would be
  contradicted by it. The skeleton offers it to new bricks; an existing brick adopts it through
  its own decision.
- **Prose wraps near 100 columns.**
- **Product docs align by headings.** `PROJECT.md` and `README.md` share a heading skeleton, not
  text; `BACKLOG.md` stays free-form because it is a ledger of each product's own decisions.

## Changing the template

The template follows the governance it defines: branch from `main`, open a pull request,
squash-merge with a self-describing body, no attribution. A change to shared text lands here first —
with both skeletons passing their Definition of Done, both instantiating cleanly, and
`family-check.py` passing on each instantiation — and is then carried to each repository in its own
pull request.
